# MOE-10 Full10 Implementation Plan

> **For agentic workers:** Required sub-skill: superpowers:executing-plans. Follow each task in order, test first, and record deviations in the SDD ledger.

**Goal:** Integrate the E31 M2D-LoRA CORAL checkpoint as Expert 10 and provide a backward-compatible Full10 extraction, gating, Kaggle, and evaluation path.

**Architecture:** A separate CORAL adapter/runtime restores the verified list checkpoint without E34 loader reuse. Profile contracts remain the source of expert order/dimensions. Existing content-addressed expert shards and schema-v2 stores are generalized to Full9/Full10; gate checkpoint versions distinguish top1_4 from schema-v2 profiles.

**Tech Stack:** Python 3.10, PyTorch, YAML, NumPy, existing unittest/pytest test suite and Kaggle scripts.

**Spec:** `docs/superpowers/specs/2026-11-20-moe10-full10-design.md`

## Global Constraints

- Preserve Experts 1–9 math, outputs, and checkpoint files.
- E31 ordered LoRA parameter list has 24 FP32 tensors; restore by authoritative model parameter traversal.
- Full10 output is `[B,1]` score plus `[B,3073]` features; gate consumes `[B,30472]` and emits ten-way Softmax weights.
- Never relabel incompatible cache shards; preserve all existing Full9 artifacts.
- No remote GPU job, upload, expert fine-tuning, or fabricated metrics.
- Run Python and tests with `conda run -n nlp`.

## Review Focus

- E31 LoRA list order differs from injection call order: test restored targets in the exact serialized parameter traversal.
- Profile changes must not affect Full9 cache IDs: test unchanged identity for Experts 1–9.
- Schema-v2 must reject profile/order/provenance mismatch: test Full9-to-Full10 rejection.
- Interrupted extraction must reuse valid shards and reject changed sample order: test both paths.
- Test split labels remain absent from inference inputs and stores: test label-free Full10 test store.

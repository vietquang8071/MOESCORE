# MOESCORE Expert 4 reproduction report

## Implementation status

The repository now contains a standalone Expert 4 workflow: training, per-epoch validation, best checkpoint selection by validation SRCC, resumable latest checkpoint, validation evaluation, and ordered test CSV export. The Google Colab notebook embeds the Python source snapshot, so a fresh runtime can run it after the user configures Drive locations. No full Expert 4 training run or XACLE benchmark is claimed.

Created or changed: expert4_repro/{audio_encoder,config,dataset,inference,losses,model,seq_coattn,text_encoder,trainer}.py; scripts/{train_expert4,evaluate_expert4,predict_expert4,check_beats,check_clap,build_expert4_notebook}.py; configs/expert4_colab.yaml; colab/Finetune_MOESCORE_Expert4.ipynb; docs/expert4_reproduction_plan.md; this report; and new Expert 4 tests. The original MOESCORE model and gate files were not modified.

## Sources and eight decisions

The source audit used MOESCORE.pdf sections 2.1–2.3 and Fig. 1, Sun_NPU_Sun_NPU.pdf sections 2–3, MOESCORE model/Basic_comp.py, model/wrapper.py, model/MOE_model.py, data/dataset.py, loss/loss_function.py, config.yaml, Train_MOE.py, README.md, local unilm/beats/BEATs.py and backbone.py, and the [official LAION-CLAP code](https://github.com/LAION-AI/CLAP). Train_MOE.py optimizes the gate, so Expert 4 has its own trainer.

1. **Independent Expert 4:** Only Expert 4 is constructed and optimized. The best checkpoint can be loaded for inference without Experts 1–3 or a gate.
2. **Text dimensions:** The pretrained CLAP text_projection maps each RoBERTa token from 768 to 512. Runtime checks require both pretrained weight matrices with shapes [512,768] and [512,512]. The released projected-token helper's first-token removal and corresponding mask slice are retained.
3. **Text source:** CLAP's RoBERTa-base text branch is initialized from the supplied CLAP state dictionary. The code constructs its architecture locally with the canonical 50,265-token vocabulary, 514 position embeddings, and one token type, then loads all text parameters from the checkpoint, avoiding a redundant roberta-base weight download. These embedding shapes are explicitly checked against the checkpoint. The tokenizer may still fetch its small vocabulary files. No roberta-large model is created.
4. **BEATs validation:** Strict checkpoint loading, checkpoint-configured 12 layers, 13 returned states including the excluded initial state, Softmax aggregation sum, 512-dimensional projection, boolean mask, finite output, and intended gradients are checked by the wrapper and check_beats.py.
5. **XACLE data:** One row per average-score CSV pair, no num_class. Optional model_ID and model_name remain metadata only.
6. **Optimization:** Physical batch size 8; Adam at 1e-5, betas (0.9,0.999); linear warmup then decay; seed 42; best by validation SRCC. Default 10% warmup and patience 10 are implementation assumptions. The 50-epoch default comes from the public config, not a confirmed Expert 4 schedule.
7. **Loss and scores:** Normalize (raw-5)/5. Clipped MSE uses strict error threshold 0.25. The released contrastive loss uses absolute error between pairwise score differences, margin 0.1, and mean divided by 2. Total is 1.0*MSE + 0.5*contrastive, with class balancing disabled. Validation metrics use predicted_normalized*5+5.
8. **Tanh:** The head is Linear(1024,2048), ReLU, Dropout(0.3), Linear(2048,1), Tanh, returning [B]. This deliberately overrides the public config's range_clipping=false.

The task's section 8 shows a minus sign for contrastive loss. It conflicts with confirmed Decision 7 and the released CombineLosses code. This implementation follows Decision 7 and the public code's positive sum. The printed paper contrastive formula also differs from the released absolute-error reduction.

## Architecture and freezing

BEATs receives mono, 16-kHz audio [B,1,160000] and true lengths. Its twelve transformer outputs are Softmax weighted and projected through LayerNorm(768), Linear(768,512), GELU, LayerNorm(512), returning [B,T_audio,512] and a boolean mask. The first ten BEATs transformer layers are frozen; the last two and the non-layer BEATs backbone parameters train, matching the public wrapper. The aggregation weights and projection train.

The CLAP audio branch is not retained. RoBERTa embeddings and its first ten layers are frozen; its last two layers and the pretrained text projection train. The two eight-head cross-attentions use key padding masks, adaptive max pooling, and concatenation to [B,1024]. The released inactive residual, normalization, and fusion-dropout lines stay inactive. Query-side padding can still influence max pooling, matching the released active path. Training prints total/trainable/frozen and component counts and checks finite gradients for representative intended parameters after the first backward pass.

## Dataset and checkpoints

The supplied local average CSVs have verified headers wav_file_name,text,average_score,model_ID,model_name. The loader also recognizes the alternate wave_file_name and average_semantic_alignement_score names if actually present. It checks scores, metadata, duplicates, paths, and waveform finiteness; converts multi-channel WAV to mono; resamples to 16 kHz with a warning; trims/pads to 10 seconds; and retains valid lengths and row order. Test prediction ignores any score column, even if present. One actual local training example loaded: 7,500 train rows; 00000.wav yielded [1,1,160000], valid length 157,504, raw score 8.0, model ID 0, and name audiocaps.

The trainer writes best_expert4.pt, last_expert4.pt, training_config.yaml, metrics.csv, environment.json, and train.log. Both checkpoints store trainable state plus configuration and checkpoint/CSV fingerprints and a UniLM Git commit/source hash; frozen weights are reconstructed from the two pretrained files. Independent loading verifies these identities. The latest checkpoint also stores optimizer, scheduler, AMP scaler, epoch, global step, best SRCC, early-stop state, seed, and Python/NumPy/PyTorch/CUDA/DataLoader RNG state. Writes use a temporary file then replacement. Resumable checkpoints use trusted pickle loading because RNG/optimizer state contains Python objects. The pretraining smoke step does not overwrite existing experiment metrics, configuration, environment, or checkpoints.

The local BEATs file loaded with PyTorch weights_only=True: its config specifies 12 layers, its state has 250 keys, and layer 11 exists. The user's Colab run also passed the real BEATs check: 12 layers and [2,496,512] audio features. The inspected local UniLM checkout is at commit 31c5b904ca1bf2afb4c234a6675c683a4e5fc7cd. The supplied weights/laion-clap.pt required weights_only=False because it contains a NumPy scalar. Its state has pretrained text_projection weight shapes [512,768] and [512,512] and RoBERTa layer 11 weights. The local CLAP checkpoint's RoBERTa embeddings have shapes [50265,768], [514,768], and [1,768]; all 199 RoBERTa parameter shapes match the corrected locally constructed RoBERTa-base model, with no missing parameter. ## Colab instructions

Open colab/Finetune_MOESCORE_Expert4.ipynb in a GPU Colab runtime with Python 3.12 (Colab past Runtime Version 2026.07 if the current runtime uses 3.13), and run cells from top to bottom. The original notebook dependency cell failed on Python 3.13 because laion-clap 1.1.6 pins NumPy 1.23.5. A later Python 3.12 attempt installed packages but hit a NumPy dtype ABI error importing CLAP in the same active kernel after replacing NumPy. The notebook now checks Python before installation, uses laion-clap 1.1.7 with NumPy 1.26.4, and performs Torch, TorchAudio, and CLAP import checks in fresh subprocesses; this corrected dependency flow still needs a Colab rerun. The first cell inspects Python, PyTorch, CUDA, GPU memory, TorchAudio, TorchCodec, FFmpeg, Transformers, and CLAP availability before installation. The notebook mounts Drive, embeds the reproduction source, and uses a supplied UniLM Git checkout or a sparse clone of Microsoft's official beats directory; environment.json records the UniLM commit. A resumed or prediction-only run checks out the recorded commit when using the notebook-managed checkout. Dataset and pretrained checkpoints are read from Drive, with bounded discovery and an error on multiple matches. Test metadata discovery recognizes test_average.csv and test.csv; set TEST_CSV explicitly when both are present.

Set MODE=train_and_predict, DRIVE_ROOT, DATASET_ROOT or individual TRAIN_CSV, VALIDATION_CSV, TEST_CSV, TRAIN_AUDIO_DIR, VALIDATION_AUDIO_DIR, TEST_AUDIO_DIR, BEATS_CHECKPOINT, CLAP_CHECKPOINT, and a required OUTPUT_DIR. The exact Drive layout is unknown and no fixed Drive data/checkpoint path is assumed. Run all cells. The notebook inspects both checkpoints, performs a real batch-eight forward/backward/optimizer smoke step, trains, evaluates validation, and writes test_predictions.csv. The DataLoader keeps a final smaller training batch when the row count is not divisible by eight, so its pairwise loss is computed on those remaining examples. If CUDA runs out of memory at batch 8, it stops explicitly; gradient accumulation is not silently substituted because the pairwise loss depends on jointly present examples.

To resume after a disconnection, retain the same configuration and OUTPUT_DIR, set RESUME_CHECKPOINT to OUTPUT_DIR/last_expert4.pt, keep MODE=train_and_predict, and rerun all cells. For inference only, use MODE=predict_only, set BEST_CHECKPOINT plus the test metadata/audio and pretrained paths, and rerun. The validation command is scripts/evaluate_expert4.py; the test command is scripts/predict_expert4.py. Both load the best Expert 4 checkpoint independently.

For a normal Python environment, fill configs/expert4_colab.yaml and run scripts/train_expert4.py --config configs/expert4_colab.yaml --smoke-test, then the same command without --smoke-test. Use --resume OUTPUT_DIR/last_expert4.pt for continuation. Evaluation and prediction scripts accept --config and --checkpoint OUTPUT_DIR/best_expert4.pt.

## Challenge eligibility and export format

No XACLE 2027 rules or submission-format file was found with the local dataset. The 2027 baseline inference utility writes wav_file_name,pred_score, but that is not confirmed as the official submission schema. This pipeline writes a generic CSV with identifier, text, metadata, normalized prediction, and raw prediction; submission formatting remains unverified. Test data is never used for optimization or checkpoint selection. The implementation generates no training audio and introduces no fixed ensemble. BEATs and LAION-CLAP are external pretrained models; organizer approval and disclosure of their pretraining data are required before claiming challenge eligibility.
